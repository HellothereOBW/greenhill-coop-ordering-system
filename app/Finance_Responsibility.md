# Finance Responsibility
Project: Greenhill Food Co‑op Online Ordering System

## 1. Financial Responsibilities

### Client Side (Greenhill Food Co‑op)
1. **Budget Approval**
Review and approve the overall project budget for this online ordering system. Evaluate costs of development, documentation delivery and optional maintenance services to ensure they fit within the co‑op’s available funds.

2. **Milestone‑based Payment Execution**
Make payments according to contract payment terms after verifying vendor deliverables and signed acceptance documents.
- Check invoices and banking information;
- Complete internal financial book‑keeping for digital‑transformation project expenses.

3. **Cost Change Control**
For any requirement changes outside original scope, participate in assessing extra costs. Additional work will only be funded with a formal written change order. Verbal requests will not trigger extra payment.

4. **Budget Risk Control**
Monitor total project spending to avoid budget overrun. Assess financial impact caused by project delays or extra services.

5. **Financial Archive Management**
Store contracts, price proposals, change orders, invoices, payment receipts and acceptance documents for internal audit and compliance review.

### Vendor Side
1. **Provide itemized pricing**
Offer clear breakdown of costs including requirement analysis, system development, documentation, acceptance‑phase support and optional post‑delivery maintenance. No hidden fees.

2. **Issue valid invoices**
Provide proper invoices and correct bank account information when reaching each payment milestone.

3. **Estimate extra work in advance**
If client requests features beyond original project scope, provide formal cost estimation before starting additional tasks. Do not perform extra work without prior written agreement.

4. **Internal cost control**
Complete deliverables within the agreed budget. Notify the client pro‑actively if internal cost risks appear.

5. **Intellectual Property condition**
Full intellectual‑property rights transfer for all source code and documents will only take effect after receiving full payment from the client.

## 2. Key Financial Milestones
| Milestone | Financial Action | Responsible Party |
|---|---|---|
| Contract signed | Pay 35% initial payment | Client finance; Vendor issues first‑phase invoice |
| Core features finished & draft documents submitted | Pay 45% progress payment | Client reviews deliverables then pays; Vendor issues second‑phase invoice |
| Final demo passed & project acceptance signed | Pay 20% final balance payment | Client full acceptance; Vendor issues final invoice |
| (Optional) Purchase post‑delivery maintenance service | Pay maintenance service fee | Both parties sign supplementary service agreement |

> Rule: Corresponding payment can be withheld if milestone deliverables are not completed and accepted.

## 3. Financial Risk Control Rules
1. **Scope creep risk**: Any new requirement outside RFP and WBS must go through formal change‑order process with cost evaluation and written approval.
2. **Project delay risk**: If delay is caused by the vendor, deduction can be applied according to contract terms. If delay comes from client‑side factors, both sides renegotiate payment timeline.
3. **Budget overrun**: When projected total cost approaches budget ceiling, project manager must notify finance team immediately, pause new feature requests and apply for new budget approval.
4. **IP constraint**: Source code and document ownership fully transfer to Greenhill Food Co‑op only upon full payment completion.

## 4. Deliverable Checklist Before Payment
Before releasing each payment, project stakeholder shall confirm:
- [ ] Milestone‑related functions are fully delivered
- [ ] Required project documents (Confluence handover docs, README deployment instructions etc.) are completed
- [ ] Signed milestone acceptance document is available
- [ ] Valid vendor invoice has been received

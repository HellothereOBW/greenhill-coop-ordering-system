# Definition of Done
Project: Greenhill Food Co‑op Online Ordering System

This Definition of Done (DoD) defines the unified completion criteria for all user stories, development tasks and project deliverables. A task or user‑story item can be regarded as fully completed **only when all the following conditions are satisfied**.

## Code‑related Criteria
1. All core acceptance criteria of the user story have been implemented.
2. The program can start and run without fatal crashes.
3. Source code follows consistent naming conventions and code style. Key business logic has necessary code comments.
4. At least one team member has completed code review; major defects and logical problems are fixed.
5. Basic corresponding unit test cases are written and passed. No blocking bugs remain.

## Documentation Criteria
1. Related technical documents are updated in Confluence or local project documents.
2. If new functions are added, the README deployment and operation instructions are updated synchronously.
3. The deliverable matches requirements recorded in the RFP and WBS work breakdown structure.

## Acceptance & Business Criteria
1. Functions can meet real business scenarios of Greenhill Food Co‑op.
2. Manual simple verification is completed by team members.
3. No high‑priority and medium‑priority unresolved bugs.
4. If this task belongs to a milestone deliverable, milestone‑check records are filled in.

## Exclusions
Definition of Done does not mean 100% perfect product. Minor cosmetic suggestions or future‑optimization ideas can be recorded in product backlog for subsequent sprints, and will not block current‑task completion judgment.
